Node cue 시각화 — 3가지 옵션 비교

목표: loop / revisit / dead-end를 attention cue로 표시. 색·크기는 이미 "안에 있는 action step 수"를 인코딩 중이므로, cue는 다른 visual channel을 써야 함. "own"(이 노드 자신) vs "rollup"(하위 layer에서 발견) 구분도 필요.

↻ loop ↩ revisit ⛔ dead-end ■ filled = own layer □ outlined = rollup (하위 layer)

A. Glyph chiclet stack

노드 우상단에 작은 칩 1~3개. 글리프로 종류 구분, fill/outline로 own/rollup 구분.

장점: 종류를 한눈에. URL 노드만 봐도 "안에 loop 있구나" 즉시 파악.
단점: 칩이 최대 3개라 노드 옆 폭 차지. 화면 줌아웃 시 글리프 식별 어려움.

● filled red = own에 cue 있음 ○ outlined = rollup만 (own 깨끗) 숫자 = 총 cue 수

B. Single severity badge

노드당 1개 배지만. 숫자=총 cue 수, fill 여부=own 여부. 종류(loop/revisit/dead-end) 구분은 hover tooltip / drill-in에서.

장점: 노이즈 최소. 노드 옆 폭 일정. 줌아웃해도 빨간 점이 attention 끌기 좋음.
단점: "loop인지 dead-end인지" 한눈에 모름 — drill하거나 hover 필요. 분류 의미는 약함.

⭕ full ring = loop ◠ top half arc = revisit ▼ bottom notch = dead-end solid = own / dashed = rollup

C. Halo arcs (orbital decoration)

노드 둘레에 위치별 마크: 전체 링=loop, 상단 반호=revisit, 하단 노치=dead-end. solid/dashed로 own/rollup 구분.

장점: 글리프 없이 시각적으로만 표현. 폭 안 늘어남. 셋 다 있어도 한 노드 안에서 정리됨.
단점: 위치 의미를 학습해야 함. 작은 줌에서 dashed 식별 어려움. current/running/selected stroke와 충돌 가능성 (해결책 필요).

참고 — 모든 옵션 공통: 노드 본체의 fill(viridis)와 radius(visits 기반)는 그대로 유지. cue는 그 위에 얹는 layer입니다. 또한 edge 쪽에서도 보조 시각화 가능 (loop = self-arc, revisit = back-edge dashed)인데, 그건 drill-in 했을 때 active layer에서 자동으로 그려지므로 이번 결정은 "상위 layer에서 노드만 봐도 알 수 있게 하는 cue"에 집중.
